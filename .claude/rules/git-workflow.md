# Git・Pull Request ルール

このRepositoryは公開している。
ポートフォリオ（my-portfolio の Works）に載せると、マージ済みPRのタイトルと本文がActivityとしてポートフォリオに公開される。
PRのタイトルと本文は、閲覧者（採用担当・エンジニア）が読む前提で書く。

## ブランチ

- main へ直接コミットしない。
  作業はブランチを切ってPRでマージする

- ブランチ名：`<type>/<短い説明>`（例：`feat/day-next-plan`、`fix/notify-line-text`）

## コミットメッセージ

Conventional Commits形式で書く。

```text
<type>(<scope>): <内容>
```

| type | 用途 |
| --- | --- |
| feat | 機能の追加 |
| fix | 不具合の修正 |
| perf | 性能の改善 |
| refactor | 挙動を変えない改善 |
| docs | ドキュメントの追加や修正 |
| style | 見た目に影響しないコード整形 |
| test | テストの追加・修正 |
| build / ci | ビルド設定・ワークフロー |
| chore | 上記以外の雑務（依存関係の更新など） |

- scope は画面か機能の名前
  - 画面：`start`（はじめに）/ `create`（しおりを作る）/ `plan`（予定・集合を書く）/ `day`（当日の画面）/ `notify`（LINE で知らせる）/ `items`（持ち物）/ `split`（割り勘）
  - 画面をまたぐもの：`theme`（色・文字などのトークン）/ `refresh`（最新の取り直し）/ `offline`（電波がないとき・Service Worker）/ `db`（D1・マイグレーション）/ `cleanup`（自動削除の Worker）等
  - Repository全体の設定・ルール：`repo`
- 内容は日本語で簡潔に書く

## Pull Request

### タイトル

コミットメッセージと同じ形式にし、`: ` の後ろを**閲覧者が読んで分かる日本語**で書く。
この部分がActivityの見出しになる。

```text
○ feat(day): 集合の時間が変わったら当日の画面で変わる前と後を並べて見せる
○ fix(notify): LINE に送る文に変更前の時刻が入らない問題を修正
× feat(refresh): visibilitychange で refreshAll を呼ぶ    # 実装の言葉になっている
× fix: いろいろ修正                                    # 何をしたか分からない
```

### 本文

最初の段落がActivityの要約になる。
何を変えて、使う人にとって何が良くなったかを1〜2文で書く。

```markdown
集合の時間や場所が変わったとき、当日の画面で古い値に二重線を引き、新しい値を朱で見せるようにした。LINE を遡らなくても、最新の集合が分かる。

## 変更内容
- …

## 確認方法
- …
```

- 最初の段落に、実装の詳細・作業メモ・チェックリストを書かない（見出し以降に書く）
- 公開してよい情報のみを書く（下の「公開してよい情報」）

### ラベル

ポートフォリオが Activity を作るときに読む。

| ラベル | 意味 |
| --- | --- |
| `tech:<id>` | ActivityのTechを指定する（my-portfolio の `data/tech.yml` の id）。付けない場合は作品のTechを引き継ぐ |
| `activity:skip` | Activityに載せない（type が feat / fix 等でも除外する） |

- chore / ci / build / test / style のPRは自動で除外されるため、`activity:skip` は不要

## 公開してよい情報

コード・コミット・PR は、すべて公開される前提で書く。

- 書かない・コミットしない：`.env`・`.dev.vars`・Cloudflare の API トークン・APIキーなどの秘密の値

- 書かない・コミットしない：しおりのリンク（URL の中の鍵）。
  知っている人はだれでも、そのしおりを見たり書き換えたりできるため

- 書かない・コミットしない：実際の旅行の中身（行き先、日程、集合場所、泊まる所、参加者の名前）。
  テストやサンプルのしおりは、作り話にする

- 書かない：住所・電話・メール・生年月日などの個人情報、所属企業名、家族構成など私生活が分かる内容

- コミットしない：`.claude/users/`（個人の作業用のファイル。`.gitignore` で外している。強制追加しない）
