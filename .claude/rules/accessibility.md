# アクセシビリティの約束事

段取りさんは **WCAG 2.1 レベル AA** に合わせて作る。
画面・部品・トークンを作るとき、[デザインの約束事](design-principles.md) と一緒に確認する。
2つがぶつかったら、こちらを優先し、見た目の方を直す。

番号（1.4.3 など）は WCAG の達成基準。
使う人の多くはスマホのブラウザ（iPhone の Safari、Android の Chrome）で開く。

## 1. 色のコントラスト（1.4.3・1.4.11）

| 対象 | 地の色との比 |
| --- | --- |
| 文字（本文・ラベル・ボタンの文字・数字の単位） | 4.5:1 以上 |
| 大きな文字（24px 以上、または太字で 18.66px 以上） | 3:1 以上 |
| 部品の形（入力欄の枠、スイッチ、選んだタブの印、フォーカスの枠） | 3:1 以上 |
| 意味のある図（今の予定の線、変わった所の二重線、まだ読んでいない変更の点） | 3:1 以上 |

- **ライトとダークの両方で測る**。
  片方だけ足りていても通さない

- 文字の色は、すべての面（`surface` と `surface-container` の段階）の上で足りるようにする。
  一番濃い面（`surface-container-highest`）で足りなくなりやすい

- 罫線の色は飾りの線にだけ使う。
  部品の形（スイッチ・入力欄・チェックの枠）には、3:1 以上の線の色を使う

- 使えない状態の部品と、ただの飾りは、比の決まりから外れる

- トークンを足したり変えたりしたら、比を測ってトークンの CSS のコメントに書いておく

## 2. 色だけで伝えない（1.4.1）

色には意味がある（青＝操作、朱＝変わった、緑＝いま、赤＝消す・間違い）が、**色が見分けられなくても分かる**ようにする。

- 変わった所は、朱の色に加えて、二重線と「直しました」の文字で分かるようにする
- 今の予定は、緑の色に加えて、左の線と「いま」の文字で分かるようにする
- まだ読んでいない変更は、点に加えて数でも示す
- 消す操作は、赤に加えて「消す」と言葉で書く
- 入力の間違いは、赤い枠だけでなく、何が違うかを文で出す（3.3.1）

## 3. 文字の大きさと余白（1.4.4・1.4.10・1.4.12）

- ブラウザの拡大や、端末の文字の大きさを **200% にしても**、文字が切れたり重なったりしない。
  文字の大きさは `rem` で書き、`px` で固定しない

- 拡大を止めない（`<meta name="viewport">` に `user-scalable=no` や `maximum-scale` を書かない）

- 高さを決め打ちした箱に文字を入れない。
  文字が大きくなったら、折り返すか、縦に伸びるか、スクロールする

- 横幅 320px でも、横スクロールなしで読める

- 画面は縦・横のどちらの向きでも使える（1.3.4）。
  向きを固定しない

## 4. 触る・押す（2.5.x）

- 押せる部品は 48px 四方以上（`--touch-min`）。
  見た目が小さくても、押せる範囲は 48px 取る

- なぞる操作（並べ替えなど）には、1本指で押せる代わりのボタンを置く（2.5.1）

- 押した瞬間ではなく、指を離したときに動かす。
  離す前に指をずらせば取り消せる（2.5.2）

- ボタンに見えている文字と、読み上げの名前を合わせる（2.5.3）。
  「LINE で知らせる」と見えているなら、読み上げも「LINE で知らせる」から始める

## 5. 読み上げ（VoiceOver・TalkBack）で使える（1.1.1・1.3.1・4.1.2）

- 意味のある画像・アイコン・図には、名前を付ける（`alt`、`aria-label`）

- 飾りだけのもの（区切りの線、アイコンの横に同じ言葉があるときのアイコンなど）は、読み上げから外す（`aria-hidden="true"`、`alt=""`）

- アイコンだけのボタンにも、何をするかの名前を付ける（「閉じる」「設定」）

- できるだけ HTML の部品（`button`・`a`・`input`・`dialog`・`details`）をそのまま使う。
  `div` に役割を付けて作り直さない

- スイッチ・タブ・チェックは、今の状態（オン／オフ、選ばれている）も読み上げられるようにする

- 見出しは見出しとして伝える（`h1`〜`h3`）

- 予定の一覧は、一覧として伝える（`ol`・`li`）。
  今の予定には「いま」、変わった予定には「変更：9:00 から 9:30」のように、見た目と同じことを読ませる

- 「ラベルを上、数字を大きく、単位を小さく」の数字は、1つにまとめて読ませる（例：「1人あたり 3,200 円」）

## 6. キーボードとフォーカス（2.1.1・2.4.3・2.4.7）

外付けのキーボードや、スイッチで操作する人もいる。
幹事はパソコンでしおりを作ることもある。

- すべての操作が、タッチ以外（Tab・矢印・Enter）でもできる

- フォーカスの動く順は、見た目の順（上から下、左から右）と同じ

- フォーカスが今どこにあるか、見える。
  地の色と 3:1 以上の 2px の線で、部品のまわりに示す（`:focus-visible`）

- フォーカスが閉じ込められて抜けられない所を作らない（2.1.2）。
  紙（`<dialog>`）を閉じたら、開く前のボタンにフォーカスを戻す

## 7. 時間と動き（2.2.x・2.3.1）

- 自動で消えるお知らせに、操作のボタンを置かない。
  置くなら、自分で閉じるまで出しておく

- 時間切れで操作ができなくなる画面は作らない。
  必要なら、延ばせるようにする

- 1秒に3回より多く点滅させない

- 5秒より長く自動で動き続けるものは、止められるか、`prefers-reduced-motion` で止まる

## 8. 状態の知らせ（4.1.3）

画面を移らずに変わったことは、読み上げにも伝える（`aria-live="polite"`）。

- 自分の操作の結果（保存した、LINE に送る準備ができた）は、すぐに伝える

- 最新を取り直して、ほかの人の変更が入ったときは、1件ずつ読み上げず、まとめて伝える（例：「予定が2件変わりました」）。
  入力の途中で、読み上げに割り込まない

## 9. 言葉と入力（3.1.1・3.2.x・3.3.x）

- `<html>` には `lang="ja"` を付ける

- 同じ働きのボタンは、どの画面でも同じ名前・同じ場所にする（3.2.3・3.2.4）

- 入力欄に値を入れただけで、勝手に画面が移ったり、みんなに知らせたりしない（3.2.2）

- 入力欄には、見える名前を付ける（`label`）。
  プレースホルダーだけで済ませない（3.3.2）

- しおりを消すなど、取り消せない操作の前には確かめる。
  消したあとに「元に戻す」を出せるなら、それでもよい

---

## 確かめ方

- 画面を作ったら、iPhone の VoiceOver と Android の TalkBack をオンにして一通り触る
- ブラウザを 200% に拡大し、端末の文字の大きさを一番大きくして、崩れないかを見る
- 自動のテストでは axe（`@axe-core/playwright` など）で調べる
- ブラウザの Lighthouse でも見る

## 例外

ほかのアプリやブラウザが出す画面（LINE の送り先を選ぶ画面、ホーム画面への追加）は、段取りさんでは直せないので対象外。
