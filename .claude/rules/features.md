# 使い方の約束事

画面ごとに、どう動くかの決まり。
計算や表示の条件は、ここに書いたことからテストを書く（[SvelteKit の約束事](sveltekit.md) 5章）。
時刻の扱いは [コードの約束事](code.md) 2章、保存と同時に直したときは [Cloudflare の約束事](cloudflare.md) 1章に書く。

## 1. 旅行の前・当日・旅行のあと

日本時間の今日で決める。

| 名前 | いつ |
| --- | --- |
| 旅行の前 | はじめの日より前 |
| 前日 | はじめの日の前の日（旅行の前の一部） |
| 当日 | はじめの日から終わりの日まで。終わりの日の予定が次の日にまたがるときは、その予定の終わりまで延ばす |
| 旅行のあと | 当日より後 |

- 予定のページの一番上には、旅行の前は「旅行まで あと n 日」だけを出す。
  当日は「次は」に、時刻・あと何分・やること・場所と地図の4つだけを出す。
  旅行のあとと、当日に次の予定が無いときは、何も出さない

- 開いたときのタブは、旅行の前は1日目、当日は今日の日、旅行のあとは1日目にする。
  終わりの日から次の日にまたがっている間は、終わりの日にする

## 2. 予定の時刻と並び

- 始まりの時刻は、空でもよい。
  空の予定は、その日の下の「時刻を決めていない予定」に出し、「いま」と「次は」にしない

- 終わりの時刻も、空でもよい。
  始まりと同じ時刻なら、空と同じに扱う。
  始まりが空で、終わりだけがある予定は、保存しない（入力の間違いとして文で出す）

- 終わりが始まりより早ければ、次の日に終わる予定にする。
  「23:00〜翌6:00」と出し、次の日のタブの一番上にも「前の日から」と出す

- 予定は、始まりの時刻の順に並べる。
  同じ時刻の予定と、時刻が空の予定は、並び順（`position`）の順にする

- 「いま」は、始まりから終わりまでの予定にする。
  終わりが空なら、次に始まる予定の始まりまで、それも無ければその日の終わりまでにする。
  2つ以上が重なったら、あとから始まった方にする

- 「次は」は、今より後に始まる、いちばん早い予定にする。
  当日でなければ出さない

- 場所の文字から、Google マップを検索するリンクを作る。
  地図のための欄は持たない

- メモの中の URL は、押せるリンクにする。
  `http:` と `https:` のものだけにし、文字の頭ではなく `new URL()` の `protocol` で見分ける

- メモと旅の名前の欄の下に、「病気やカードの番号などは書かないでください」と、ふつうの文で書き添える。
  リンクを知る人はだれでも見られるため

## 3. 日にちを縮めたとき

- はみ出した日の予定は、消さない。
  予定のページの一番下に「旅行の日にちの外になった予定」として残す

- 日にちを戻したら、元の日に戻す。
  要らなければ、1つずつ消してもらう

## 4. 変わった所の印

当日に知りたいのは「前に知っていた値と、今の値」なので、出す場所をしぼる。

- 出すのは、ほかの人が予定の時刻か場所を直したときだけにする。
  旅行の前日と当日の直しだけを数える

- 次のときは出さない。
  - 自分の直し
  - やること・メモの直し
  - 前日より前の直し

- 最初の値に二重線を引き、今の値を朱で出し、直した人を並べる。
  続けて直されたら「最初の値 → 今の値」にする

- 最初の値に戻ったら、印を消す

- 最後に直した時刻から24時間たったら、印を消す

- 「読んだ」のボタン、下のメニューの点、「変更 n件」は持たない

## 5. 予定を消す・直したことを知らせる

- 予定は消せる。
  消した直後に、下のお知らせで「元に戻す」を出す。
  このお知らせは、自分で閉じるまで出しておく（[アクセシビリティの約束事](accessibility.md) 7章）

- 時刻か場所を直して保存したときと、予定を消したときは、下のお知らせに「みんなに知らせる」を出す。
  押すと、端末の共有の画面（`navigator.share`）を開く。
  開けないブラウザでは、送る文をコピーする

- 送る文には、変わる前と後、消した予定、しおりのリンクを入れる

## 6. 一緒に行く人と呼び名

- リンクを初めて開いた人には、呼び名を入れてもらう。
  だれのしおりか（幹事の呼び名）、旅の名前、日にちを見せて、その下で聞く

- もう名前を入れた人を並べ、押すだけでその人として開けるようにする。
  保存が消えたときや、ブラウザが変わったときに、同じ人が二重に入らないため

- 呼び名は端末で覚え、2回目からは聞かない

- 直せる・消せるのは、自分と、「足す」で足した人だけにする。
  幹事は消せない

- 一緒に行く人を消す前に、確かめの画面を出し、その人が立て替えた分も消えることを書く。
  消したら、その人が持っていく人だった持ち物は、持っていく人を決めていない形に戻し、その人の持ち物のチェックも消す（立て替えは8章）

- だれでも「その人として開く」ことができるので、「○○さんが直しました」は本人が直したことを保証しない。
  画面の言葉で、本人の証のように見せない

## 7. 持ち物

- 「みんなで使うもの」はだれか1人が持っていき、「それぞれ持っていくもの」は全員が持っていく

- 持ち物の一覧は、みんなで同じにする。
  チェックは人ごとにサーバーに置き、画面には自分のチェックだけを出す

## 8. 割り勘

- 立て替えの「割る人」は、初めは一緒に行く人の全員にする。
  割らない人は、そのとき外す

- 1人あたりは、金額を割る人の数で割り、1円未満を切り捨てる。
  余りは、立て替えた人が持つ。
  精算の下に、そう書き添える

- 精算は、払う回数が少なくなるように組む。
  差し引きで払う額の一番大きい人から、受け取る額の一番大きい人へ払う、をくり返す。
  額が同じときは、名前を入れた順にする（毎回同じ答えにするため）

- 精算の行を押すと、その人の「分・立て替えた分・差し引き・払い先」を出す。
  払い先をまとめているので、立て替えてもらった人と払う相手が違うことがある、と書き添える

- 精算の行の「払った」は、だれでも押せる。
  押した人の呼び名を残し、「払いました（○○さんが書きました）」とうすく出す

- 一緒に行く人を消したら、その人が立て替えた分を消し、割る人からも外して、精算を計算し直す

## 9. 読めない所としおりを消すこと

- 読めない欄・決まりに合わない欄は、その所だけを「表示できない名前」などと出す（[コードの約束事](code.md) 5章）。
  しおり全体を「開けません」にしない

- 読めない欄にも、読めるときと同じ決まりで「直す」「消す」を出す。
  一緒に行く人の名前なら6章に従い、幹事の名前には「消す」を出さない

- しおりを消す操作を置く。
  個人情報の消去の請求を、画面で受ける手続にするため（[Cloudflare の約束事](cloudflare.md) 7章）。
  リンクを知る人はだれでも押せる（ログインが無く、幹事だけに限る確かな方法が無いため）。
  押したら確かめの画面を出す。
  消してから7日の間は、リンクを開くと「このしおりは消しました」と「元に戻す」を出す（いたずらで消されても戻せるようにするため）。
  旅行が終わって自動で消したときの文（[Cloudflare の約束事](cloudflare.md) 4章）とは分ける

- しおりを作る・名前を入れるの送るボタンの下に、プライバシーポリシーへのリンクを、ふつうの文で置く。
  お知らせの箱にしない（[デザインの約束事](design-principles.md) 5章）。
  送る前に1回の操作で届くようにするため（個人情報保護法 21条2項）
