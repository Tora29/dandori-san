# デザインの約束事

段取りさんの見た目を決めるときの基準。
画面・部品・トークンを作る前に確認し、ここに反する見た目は提案しない。
迷ったらここに戻る。
値そのものはトークンの CSS（モックでは `.claude/users/mock/assets/tokens.css`）に置き、ここには「なぜそうするか」だけを書く。
色・文字・部品の大きさは、[アクセシビリティの約束事](accessibility.md)（WCAG 2.1 AA）も満たすこと。

**一言でいうと：調整さんのように、だれでも迷わず使える道具。**
使うのは、駅のホームや移動中に、片手で「次は何時にどこ」を確かめるとき。
リンクを受け取るのは、親や親戚、職場の人かもしれない。
見た目で楽しませるより、速く開いて、すぐ分かることを選ぶ。

## 1. 当日は「次」が主役

- 当日の画面では、「次は何か」と「集合は何時にどこか」を一番上に大きく出す。
  ほかの部品は、それを邪魔しない

- 前に開いたときから変わった所は、ひと目で分かるようにする。
  変わっていない所は、目立たせない

## 2. 決まりは Material 3 から借りる

色・文字・余白・形の決まりは、[Material 3](https://m3.material.io/) にそろえる。
自分で決まりを作り込まない。

- 借りるのは決まりだけ。
  Material の部品集や Web コンポーネント（`@material/web` など）は入れない。
  普通の HTML と CSS で、Material 3 の形と大きさに合わせて作る

- 色は Material 3 の色の役割（`primary`・`surface`・`on-surface` など）で使う。
  色の値を部品の中に直に書かない

- 文字の大きさは Material 3 の段階（`display`・`headline`・`title`・`body`・`label`）から選ぶ

- 余白は 4 の倍数。
  押せる部品は 48px 四方以上

- 角の丸みは Material 3 の段階（小・中・大）から選ぶ

## 3. Android らしさを持ち込まない

日本では、使う人の6割ほどが iPhone。
Material 3 の中でも、Android アプリに見える部品は使わない。

- 使わない：浮いた丸いボタン（FAB）、押すと広がる波紋、大きく伸び縮みする上のバー、横から出るメニュー（ドロワー）

- 使う：普通のボタン（塗り・線・文字だけ）、入力欄、一覧、タブ、下のメニュー（スマホ）、横のメニュー（パソコン）、下から出る紙（スマホ）、真ん中に出る紙（パソコン）

## 4. 動きは使わない

- 画面の切り替え、紙の出入り、変更の反映に、アニメーションを付けない。
  すぐに切り替える

- 最新を取り直して、ほかの人の変更が入っても、画面を動かして知らせない。
  変わった所の印（5章）で知らせる

- 例外は、押している間に色が少し変わること（Material 3 の状態の重ね）だけ。
  マウスを乗せたときも、同じうすい重ねだけにする

## 5. 飾らない

- 質感・イラスト・グラデーション・飾りの影を使わない。
  面の区別は、Material 3 の面の色の段階（`surface-container` など）と、細い線で付ける

- 文字は端末に入っているものを使う。
  Web フォントを読み込まない（日本語のフォントは重く、通信の悪い場所で開くのが遅くなる）

- **色の付いた箱にアイコンと太字の見出しを入れた「お知らせの箱」を作らない**（安心や注意を伝える定番の形で、AI が作った画面に見える）。
  伝えたいことは、関係のある所のすぐ下に、ふつうの文で書き添える

- 意味を持つ印は2つだけにする
  - **変わった所**：古い値に二重線を引き、横に新しい値を朱で書く。
    「何が変わったか」を伝える、段取りさんの中心の機能
  - **今の予定**：行の左に緑の線と「いま」の文字

## 6. 色

| 色 | 意味 | 使う場所 |
| --- | --- | --- |
| 青（`primary`） | 操作 | 一番大事なボタン、選んでいるタブ、リンク |
| 朱（追加の色 `changed`） | 変わった | 変わった所の新しい値、まだ読んでいない変更の点 |
| 緑（追加の色 `now`） | いま | 今の予定の印、「あと何分」 |
| 赤（`error`） | 消す・間違い | 消す操作、入力の間違い。必ず言葉も添える |

- ほかは、面の色と文字の色の濃淡だけ

- 色は1つの基本の色（今は青）から、Material 3 のやり方で作る。
  基本の色を変えるときは、全部の役割を作り直す

- ライトとダークは、端末の設定（`prefers-color-scheme`）に合わせる。
  色の意味はライトとダークで変えない

## 7. 文字

- 端末の文字（iPhone はヒラギノ、Android は Noto Sans JP）を使う

- 数字は桁をそろえる（tabular-nums）

- 等幅のフォントは使わない（プログラマーの道具に見える）

- 小さい文字の字の間を、大きく空けない（ひな形の癖に見える）

## 8. 言葉は短く、やさしく

- 中学生でも分かる言葉で、1文を短くする。
  「〜しましょう！」のような押しつけや、感嘆符は使わない。
  カタカナ語より日本語を選ぶ（「スケジュール」ではなく「予定」）

- **見出し・ボタンには句読点を付けない**。
  「〜が、〜に〜ます。」のように読点でリズムを作り、句点で締める書き方は、AI が作る文の型に見える。
  区切りは改行と空きで作る

- 句読点は、説明の文（本文）でだけ普通に使う

- 主語は使う人にする。
  アプリが勝手にやるような受け身の言い方にしない（「共有されます」ではなく「みんなに届けます」）

- ボタンには、押すと何が起きるかを書く（「共有」ではなく「LINE で知らせる」）

- 開発の中だけで使う言葉（「段階 3」「MVP」など）を、使う人に見せない

- 折り返しは言葉のまとまりの間でだけ起きるようにし、ブラウザまかせにしない

---

## 例外

ほかのアプリやブラウザが出す画面（LINE の送り先を選ぶ画面、ホーム画面への追加）は、段取りさんでは作らないので、その見た目のまま使う。
